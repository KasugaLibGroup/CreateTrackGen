# Create Track Gen — Create Track Generator Plugin

[![BlockBench](/plugin_title.png)]([./LICENSE](https://www.blockbench.net/wiki/docs/plugin/))

[![MIT License](https://img.shields.io/badge/License-MIT-blue)](./LICENSE)
[![README ZH-CN](https://img.shields.io/badge/Readme-中文-green)](./README.zh-cn.md)
[![BlockBench](https://img.shields.io/badge/Blockbench-Model-yellow)]([./LICENSE](https://www.blockbench.net/wiki/docs/plugin/))

A Blockbench plugin that takes the **left rail / right rail / tie** part models, plus track gauge,
track height and whole-model Y offset, and automatically generates the **9 track shapes** compliant
with Create Mod's track conventions (straight / 45° diagonal / ascending / portal / 4 crossings;
`z_ortho` / `ascending_n/e/w` / `teleport_x` / `cross_d1_zo` / `cross_d2_zo` are not generated
separately — their directions are expressed via the blockstates' `y` rotation), and converts the
entered gauge into the **scale constant** Create uses for curves (quadratic fit).

Optionally import two portal textures separately (`portal_track.png` / `portal_track_mip.png`):
`portal_track` covers the track/ties of `teleport` / `teleport_x` (defaults to the parts' own
textures); `portal_track_mip` generates the left/right overlay cubes `teleport_left` /
`teleport_right` wrapping each half of the ties (excluding the rails) with the mip texture (not
generated by default). When both are absent, the portal track matches `z_ortho` / `x_ortho`
(structure follows Create's original `teleport.json`).

> The interface (API) reference of the source, in Chinese & English, lives in [`docs/`](docs/).

## Features

- **Generate track model group**: `Tools → Generate Create Tracks`
  - Provide the three parts in order — left rail / right rail / tie (import a `.bbmodel` from disk, or
    "Select a Tab" to extract the elements selected in an open tab)
  - The three parts' **texture resolutions must be identical**, otherwise generation is rejected
  - Enter the track gauge (px, 1/16 block; Create default 1600mm ≈ 25.6px, with mm/inch conversion),
    track height (px) and whole-model Y offset (px, default 0)
  - Optionally click "Import portal_track…" and "Import portal_track_mip…": `portal_track` covers the
    track/ties of `teleport` / `teleport_x` (defaults to the parts' own textures); `portal_track_mip`
    generates the left/right overlay cubes (`teleport_left` / `teleport_right`, wrapping each half of
    the ties, excluding the rails) textured with the mip (not generated by default)
  - Enter a new workspace name (default `track`); the result is generated into a **new standalone
    workspace** (model tab), with the three parts' textures imported and applied to the corresponding
    groups; **the track parent group name = that workspace name** (default `track`), looked up by the
    current workspace name on export
  - Automatically generates 9 shapes: `x_ortho / diag / diag_2 / ascending_south / teleport /
    cross_ortho / cross_diag / cross_d1_xo / cross_d2_xo` (only the models the blockstates reference;
    `z_ortho` → `x_ortho` rotated 90°, other ascending/portal directions → `y` rotation,
    `cross_d1_zo` / `cross_d2_zo` → `cross_d1_xo` / `cross_d2_xo` rotated 90°; `cross_d1_xo` =
    negative diagonal + Z straight, `cross_d2_xo` = positive diagonal + Z straight — naming is the
    opposite of the reference Kuayue)
  - **Ascending track**: like the diagonal, 3 rail segments / 3 ties (24 px long), tilted −45° about
    the center then lifted as a whole, so that **after the two user-definable offsets (track height and
    whole-model Y offset) take effect**, the lowest tie corner still lands exactly on the xz plane
    (y≥0) — a negative whole offset also pushes the ascending track back to the plane
  - **Curve-rendering base groups**: `tie` / `segment_left` / `segment_right` (the three models Create
    uses for curve rendering) **hang under the track parent group** (named after the workspace)
    alongside the directional shapes, each holding its corresponding part (cube + mesh group), laid out
    as a **track unit**: each rail is pivoted at its own model center with its center x zeroed (both
    the Java model center (8,8) and other formats' (0,0) translate to x=0, like Create's
    segment_left/right.obj), the near z end rests on the xy plane (z=0), and the rail bottom is lifted
    to track height + whole-model Y offset; the tie moves to the first tie position near the x axis of
    z_ortho (z=4), offset only by the whole-model Y offset (not lifted). The ±gauge/2 spacing between
    the rails is applied by Create at render time
  - **Workspace format auto-detection**: any part with mesh groups (a `.bbmodel` `type:"mesh"`
    element) → the new workspace is a **free model** (generic); otherwise a **Java block/item model**
- **Export track models**: `Tools → Export Track Models`, **4 export modes** (dialog dropdown)
  - **1.21.11+ new Java** (`format_version: "1.21.11"`, element rotation supports multi-axis `{x,y,z}`)
  - **1.21.11- classic Java** (no `format_version`, exactly matching the assets examples; elements use
    single-axis rotation only `{angle,axis}`)
  - **Bedrock block model** (one `minecraft:geometry` per shape + `blocks.json`)
  - **Export everything as OBJ**
  - Exports the groups under the current workspace's track parent group in the chosen mode +
    **blockstates** + texture PNGs, to a user-chosen folder
  - Models: `models/block/track/{trackId}/{shape}.json` (`x_ortho / diag / diag_2 / ascending /
    teleport / cross_ortho / cross_diag / cross_d1_xo / cross_d2_xo / tie / segment_left /
    segment_right`, 12 in total; `z_ortho` is expressed by rotating `x_ortho` 90°, `cross_d1_zo` /
    `cross_d2_zo` by rotating `cross_d1_xo` / `cross_d2_xo`; `ascending` exports only the south
    variant, `teleport` only the Z direction, the rest expressed via blockstate `y` rotations, matching
    Create/Kuayue)
  - blockstates: `blockstates/{trackId}_track.json` (shape × turn × waterlogged = 76 variants, models
    referenced as `{namespace}:block/track/{trackId}/…`; `shape=zo → x_ortho y:90`,
    `cr_pdx → cross_d1_xo y:90`、`cr_pdz → cross_d2_xo y:180`、`cr_ndx → cross_d2_xo y:270`、
    `cr_ndz → cross_d1_xo`, matching the reference Kuayue meter/guard blockstates)
  - Textures: `textures/block/track/{trackId}/{resourceName}.png` (exported deduplicated by the source
    texture file name; the Bedrock mode writes `textures/blocks/{trackId}/`)
  - On export a configuration dialog pops up: **export mode** (default classic Java) + **namespace**
    (default `kuayue`) + **track id** (default workspace name); then pick the target folder (the first
    visit requests "folder access" permission)
  - After export a **widened summary dialog** (640px) appears: summary + each warning/notice in its own
    box, fully shown
  - **Export eligibility** (not exportable → auto fall back to OBJ):

    | Element/Shape | New Java | Classic Java | Bedrock | OBJ |
    | --- | --- | --- | --- | --- |
    | Cube (single-axis rotation) | ✓ | ✓ | ✓ | ✓ |
    | Cube (multi-axis rotation) | ✓ (`{x,y,z}`) | ✗→OBJ | ✓ | ✓ |
    | Mesh group (triangle faces) | ✗→OBJ | ✗→OBJ | ✗→OBJ | ✓ |
    | Shape referencing multiple textures | ✓ | ✓ | ✗→OBJ | ✓ |

    (e.g. `ascending`'s `[-45, yaw, 0]` multi-axis rotation falls back to OBJ in the classic mode,
    consistent with Create's original.)
  - **OBJ export**: bakes all volumes / meshes in a group into a **single merged mesh** (a single `o`
    object at the root, no per-element `o`/`g` groups) so the Forge loader reads it as one; coordinates
    in block units (px/16), vt flipped, textures bound via `usemtl m_<key>` + MTL
    `map_Kd {namespace}:block/track/{trackId}/{resourceName}`; the model JSON is a `forge:obj`
    reference (`flip_v: true`)
- **Gauge conversion**: `Tools → Track Gauge Converter`, enter mm to get the Create curve scale constant
  - Anchors: 1435mm→0.755, 1600mm→0.965, 1000mm→0.525 (quadratic fit)

## Testing in Blockbench

### Step 1: Build the plugin

```bash
npm run build
```

Make sure `create_track_gen.js` appears at the project root.

### Step 2: Load the plugin

1. Open **Blockbench** (desktop, 5.x recommended).
2. Create a new Java Block project: `File → New → Java Block/Item`.
3. Drag `create_track_gen.js` into the Blockbench window (or `File → Open → Plugin` and select it).
4. A `Tools` menu should appear, with **Generate Create Tracks** and **Track Gauge Converter** under it.

> Reload the plugin: after editing the source and re-running `npm run build`, press **Ctrl/Cmd + J** in
> Blockbench.

### Step 3: Prepare the parts (choose one of two)

**Method A: import the sample parts (recommended, quickest way through)**

Use the three files under `test/sample_parts/`: `left_rail.bbmodel`, `right_rail.bbmodel`,
`tie.bbmodel`.

**Method B: use your own parts**

The three parts must satisfy:
- All Java Block format (`.bbmodel`)
- Bottom face on the xz plane (y=0)
- Left rail / right rail / tie each is one model file (or a group of selected elements in the current
  project)

**Symmetry point convention** (normalization basis, decided automatically by the model format):
- **Java Block / Item** (`java_block` / `java_item`): the symmetry point on the xz plane is **(8, 8)**
  — because this mode's canvas is 0..16 with the origin at a corner and the model center at (8,8).
  Parts can be made as large as the 0..16 canvas allows, without the "symmetric about zero" size limit.
- **Other formats** (generic/free etc.): the symmetry point on the xz plane is **(0, 0)** — the origin
  is the canvas center.

The plugin translates the symmetry point to the origin during normalization, then places the left/right
rails at ±gauge/2, so whether a part is perfectly centered does not affect the final result.

**How the gauge is measured**: `gaugePx` is the **center distance between the left and right rails**
(Create's default nominal gauge 1600mm, at "1 block = 1 m = 16px" ≈ **25.6px**). The rail part's width
should therefore be clearly smaller than the gauge, otherwise the two rails will touch. Create's
official `segment_left.obj` / `segment_right.obj` (about 2.4px wide, 4.5px tall) combined with the
default gauge 25.6px gives the correct 25.6px center-distance track.

**Track length**: one full block (16px) by default. A rail part shorter than that is tiled along the
laying direction to fill it (Create's rail segments are 8px half-blocks, two per block). Ties are laid
along the whole track at the tie interval and no longer disappear because a rail part is too short.

**Texture consistency**: the left/right rail and tie parts' texture resolutions (pixel dimensions) must
be exactly the same, otherwise a "texture resolution mismatch" pops up and generation is rejected. On
generation the three parts' textures are imported into the new workspace and applied to the
corresponding faces (left rail → left texture, right rail → right texture, tie → tie texture).

**Mesh groups**: a part may be pure cubes (Java block model) or contain mesh groups (e.g. models
imported from Create's `.obj`). If any part has mesh groups, the new workspace is a **free model**;
mesh groups are moved into the `tie` / `segment_left` / `segment_right` base groups (they do not
participate in the 9 track shapes, which are built from the cube part). The plugin bakes a mesh's
origin (world anchor) and rotation into the vertices, so meshes with a non-zero origin (e.g. a Java
model's origin (8,8,8)) are positioned at x=0 correctly.

### Step 4: Run generation

1. Click `Tools → Generate Create Tracks`.
2. Provide the sources of the left rail / right rail / tie in order:
   - Choose **Import File** → file picker → select the corresponding `.bbmodel`
   - or choose **Select a Tab…** → pick one from the open tabs; the plugin extracts the elements
     selected in that tab as the part (first frame-select the part's elements in the target tab's
     outliner)
3. Enter the **gauge** (px, 25.6 ≈ 1600mm for the sample), **track height** (px, 2 for the sample) and
   the **whole-model Y offset** (px, 0 for the sample). Pressing Enter in the mm/inch fields converts
   back to px automatically.
4. Enter a **new workspace name** (e.g. "track"). The result is placed in this **new workspace** (model
   tab), leaving the current workspace untouched; the workspace texture resolution is set to the parts'
   texture size.
5. Wait for generation to finish. The new workspace's outliner shows the parent group (workspace name),
   containing 9 child groups whose cubes are textured with the corresponding part textures, plus three
   top-level groups `segment_left` / `segment_right` / `tie` (curve-rendering base models).
6. The new workspace's model format is decided by the parts: **any part with mesh groups → free model**;
   otherwise a **Java Block/Item model** (mesh groups cannot exist in a Java model, only in a free model).

### Step 5: Verify the results

- **Straight track**: expand the `z_ortho` group — the left/right rail center distance should equal the
  gauge (default 25.6px).
- **Diagonal**: the `diag` group's elements carry a 45° Y rotation (select an element and check the
  rotation in the right properties panel).
- **Ascending**: the `ascending_*` group's elements carry a −45° X rotation, pivot at the block center
  (Java canvas xz (8,8)); 3 ties, tilted about the center then lifted as a whole, so the lowest tie
  corner still sits on the xz plane (y≥0) after the track height and whole-model Y offset.
- **Curve base groups**: the workspace has top-level `segment_left` / `segment_right` / `tie` groups
  for the left rail / right rail / tie parts (Create curve rendering). Each rail is pivoted at its own
  center (center x zeroed), near z end at z=0, bottom at track height + Y offset; the tie at z=4 (first
  tie position), bottom only +Y offset.
- **Textures**: the left/right rail and tie elements should each have their own texture (imported part
  textures in the texture list, viewable in the UV editor).
- **Portal/crossing**: the `teleport*` group contains the straight track (covered with `portal_track`
  if imported, else the parts' default textures) + the left/right overlay cubes `teleport_left` /
  `teleport_right` (generated only when `portal_track_mip` is imported; wrap each half of the ties,
  mip-textured, excluding the rails); when neither is imported it matches `z_ortho` / `x_ortho`. The
  `cross_*` groups contain the crossing elements.
- **Gauge conversion**: `Tools → Track Gauge Converter`, enter 1435 → ≈0.755; 1600 → ≈0.965.

## Track size reference sources

The generator's geometry parameters are extracted from Create's official source repo
(`Creators-of-Create/Create`, mc1.20.1/dev branch) and the `assets/tracks/` (Kuayue mod) reference
assets:

- `assets/tracks/standard/models/block/track/standard/diag_template.json` — 45° diagonal rotation scheme
- `assets/tracks/standard/models/block/track/standard/ascending_template.json` — ascending slope rotation scheme
- `assets/tracks/standard/models/block/track/standard/x_ortho.json` — straight-track layout
- `assets/tracks/standard/models/block/track/standard/cross_ortho.json` — orthogonal crossing
- `assets/tracks/standard/models/block/track/standard/tie.obj` / `segment_left.obj` / `segment_right.obj`
  — curve-rendering base models (the `tie` / `segment_left` / `segment_right` groups in the generated
  workspace correspond)
- Create source `TrackModel.java` — the procedural transform of the ascending track (vertical offset
  −0.25, slope angle rotation about Z)
