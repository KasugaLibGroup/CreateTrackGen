# `src/ui/dialog.ts` — Generate configuration dialog

A single-page dialog collecting all inputs:

- the three parts (left rail / right rail / tie) come from: importing a `.bbmodel` from disk, or
  "Select a Tab" to extract the elements selected in an open tab; the right rail additionally offers
  "Mirror from First Model" — mirroring the left rail about its central YZ plane (`mirrorPartYz`).
- gauge (px, with mm/inch conversion: pressing Enter in any field back-fills the other two) / track
  height / whole-model Y offset (px) / new workspace name.
- portal textures: two independently optional imports — portal_track covers the track/ties (defaults to
  the parts' own textures), portal_track_mip generates the left/right overlay cubes
  (`teleport_left` / `teleport_right`, wrapping each half of the ties, excluding the rails, textured
  with the mip; not generated by default).
- the workspace format is decided by the input parts: any part with mesh groups → free model
  (`generic`); otherwise Java block/item model.

Parts are collected in the dialog **without** texture prefixes; generation applies `scopeTextureKeys`
prefixes (L / R / T) so the "source key → imported Texture" mapping stays globally unique.

## Types

### `GenerateOutput`

The final output of the dialog flow.

```ts
export interface GenerateOutput {
	config: TrackConfig;
	shapes: ShapeSpec[];
	textureByKey: Map<string, Texture>;  // source texture key → Texture imported into the new workspace
}
```

## Styles

### `injectDialogStyles()`

Injects the generate dialog styles (when a document exists; safely skipped in Node smoke tests).

```ts
export function injectDialogStyles(): void;
```

## Entry point

### `runGenerateWizard()`

The full generation flow entry (single-page dialog). Returns the generation result, or `null` on
failure/cancel. Once the user fills all inputs and confirms, `onConfirm` creates the workspace and
resolves.

```ts
export function runGenerateWizard(): Promise<GenerateOutput | null>;
```
